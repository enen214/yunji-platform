# 产品基线操作与接力验收手册

适用本地候选 `feature/product-baseline-rebuild-20261027`，迁移V26。旧日期的送审/发布版本、学校scope、资料包/插件入口不适用本轮。以下操作描述为本地功能验收；真实平台发送、目标服务器上线须另验。

## 一、启动与停止

1. 在项目根目录安装 Python requirements；后台、C端、tests分别按锁文件 `npm ci`。准备 Java21、Maven3.9、MySQL8和Redis可执行程序。Windows运行器默认工具路径见本地开发说明，可用 `YUNJI_TEST_JAVA`、`YUNJI_TEST_MAVEN`、`YUNJI_TEST_MYSQL_BIN` 覆盖。
2. 执行 `python scripts/workbench.py start`，等待输出“工作台已启动”。它使用本轮随机隔离数据库和日志目录，不连接生产库。33308/16379/18088/5173/5174若被占用会拒绝，不杀其他服务。
3. C端打开 `http://127.0.0.1:5173/#/`；后台打开 `http://127.0.0.1:5174/#/login`。
4. 另开终端执行 `python scripts/workbench.py code alice`，复制两分钟单次码用于本地客户登录。工作人员可用本地测试夹具 `test1 / 666666` 或 `admin / admin123`；**仅本地测试数据，生产初始化必须bootstrap独立口令**。
5. 原终端 Ctrl+C；或 `python scripts/workbench.py stop` 请求该工作台正常停止。不要用批量 kill java/mysqld 破坏其他项目。

## 二、C端人工验收

| 场景 | 操作 | 应看到的结果 |
|---|---|---|
| 未登录浏览 | 首页看资讯、切板块、搜索 | 有公开内容；需身份操作先出现登录，可关闭返回 |
| 首页 | 看通知条、轮播、双列推荐 | 有合成内容标识；轮播进入专题；热点0内容不进推荐 |
| 三类详情 | 分别打开普通/通知/攻略 | 摘要/正文/原文按类型显示；通知有时效；攻略显示长图；分类与标签关键词完整 |
| 点击与曝光 | 先不开详情滚动，再点开 | 仅真实滚动可见触发曝光；打开后记全局已读，刷新首页/盒子排除；30秒去重 |
| 搜索 | 输入、筛选板块和标签、开启历史 | 多选板块后标签分组；过期可按开关找；分页不随新增插入打乱；下线不泄露 |
| 热词和历史 | 空搜索页、点热词、删除一条历史 | 不预填输入值；热词直接搜；历史20条、单删/清空；热门资讯为标题列表 |
| 关注 | 详情关注信息/关键词，勾选标签 | 关注后有对应盒子；不自动开外部强提醒 |
| 取消与撤销 | 管理关注取消，选择保留提醒，再撤销 | 页面可撤销；恢复关注和相应提醒版本；离页后以服务器为准 |
| 三栏盒子 | 切更替/关注更新/推送、开小盒子 | 跨栏去重；默认平铺；展开原位；多标签共享阅读/曝光 |
| 滑读 | 左右滑某条并确认已读 | 成功后从盒子移除；失败显示错误，不假装完成 |
| 强提醒 | 打开管理页看三组 | 更替/关键词/及时三栏；不出现投递账本/失败原因；本地绑定和授权仅合成 |
| 活动下载 | 活动内下载已引用文件 | 未登录要求登录；成功取回才计数；用户+活动+文件+天去重；启停立即约束新请求 |
| 我的 | 收藏、历史、反馈、资料、退出 | 收藏与关注分开；历史可清；昵称可改；手机号脱敏；头像编辑尚无入口 |

**注意**：置顶按PB-09/10豁免已读/曝光；运营强加本身不豁免生命周期或安全准入。初始页面只渲染不算曝光。后台模拟提醒处理按钮不等于真实消息发送。

## 三、管理员常用流程

### 字典与内容

1. 在内容组维护板块、标签、关键词，标签必须属于板块。已有词条尽量用别名合并语义，不建重复关键词。板块只作内容分类，不是用户学校组织。
2. 新建资讯选择类型、一个板块、至少一个标签和关键词；普通信息填一二三级；通知按类型必填二级和时间；攻略填安全长图URL。重要度1～5、热点0～30天。热点0表示不进首页/板块推荐，仍可搜索。
3. 保存直接发布。错字直接保存修正；重大变化另建一条，不覆盖原文。保存冲突409时重新加载并核对，不直接覆盖另一运营人员的新值。
4. 后台资讯服务器分页，每页20；标题搜索查询全库，不再仅筛首200条。部分字典/活动选择器仍有限量，规模扩大前需专项分页改造。

### 更替

候选由完全一致的板块/标签集合/关键词集合命中。运营确认来源和时效后决定确认或忽略。确认结束旧文并迁移关注/提醒，旧详情仍可访问；下线/删除不同。遇到循环或链深限制拒绝时不要改库绕过，检查候选关系。更替形成用户可感知通知/盒子，不静默跳过。

### 导入

按[JSON导入指南](批量导入格式与恢复指南-20261027.md)下载三类示例、替换现有分类名称。导入前在本地少量试验。回执成功/失败均逐条明确；断网后拿原批次/key续做，勿点击新批次反复制造内容。失败序号为原始数组1起始序号。修正失败行后可新批重导，已成功行无需重导。

### 文件、活动和评审

全局文件库上传一次，多活动引用；上传新版本保留历史。活动配置决定是否开放历史版本。停用禁止下载；删除前必须解除全部活动引用。云提供者缺配置返回错误，不允许生产读本地测试文件。

活动配置报名窗口、活动时间、名额和候补；用户并发报名通过事务防超卖，取消确认名额会晋升候补。真正每活动专门页面要前端按活动设计实现；通用活动模板不能当成所有活动已做完。

评审项目是全局功能，活动可引用；后台能维护材料要求、查看申请/材料、通过/驳回/补正。结论绑定具体提交版本；补正不能覆盖原材料和原结论。客户只能操作自己的申请。C端独立评审入口本期已退役。

### 提醒与事故

管理端保存时段/模板和规则；日常按用户选择聚合，提前五分钟规划。检查“通道监控”时须先看真实发送器是否就绪；当前仍为待接线。UNKNOWN、明确失败、超期在途可列事故。核实供应方任务状态、收件人和实际发送凭证，再记录结果；未知结果禁止盲目重试。对已明确失败的任务可带证据补提。

正式告警和兜底必须由项目组接真实监控后测试，当前日志 `REMINDER_INCIDENT` 只是机器可收集信号。7-17“绝不滞留”还需要通知值守、升级策略和平台侧证据，不是有一个列表就满足。

### 账号与数据

所有有效工作人员拥有统一运营权限；新建独立账号，不共用管理员。禁止停用自己的唯一当前账号；账号停用后会话不能继续业务操作。后台菜单数据库下发六组。查看统计先确认口径：分享是发起次数、点击30秒去重、曝光累计、下载是客户端确认且日去重，统计比值可能超过100%，不自动解释为概率。

## 四、测试接力记录

接收团队记录：分支、完整提交SHA、构建产物SHA、迁移历史、部署配置版本（不记密钥）、测试人、日期、实际/预期、失败日志。参考本轮报告作为重现线索，不把其通过数当目标机结果。

建议试验顺序：空库安装 → bootstrap → 登录与STAFF边界 → 类型/分类 → 手工与批量发布 → 更替与盒子 → 文件/活动/评审 → 提醒负例/事故 → 统计 → 备份新库恢复 → H5域名回环 → 微信开发工具/真机 → 供应方任务与授权/回调 → 安全审查。任一真实能力未接线保持禁用，并在交接记录登记责任和下一步。

## 五、部署团队最小输入

已确认 Linux x86_64/amd64、Docker可用；不要求无理由改动现有后端配置。接收团队提供空的试验数据库/Redis、可写持久附件目录、容器运行与域名HTTPS能力、环境变量注入方式、受控迁移权限及恢复位置。真实小程序/企微/云环境资料只通过受控密钥配置交付，不贴聊天；没有资源则相应验收保留未通过。

服务监听回环/API代理、证书、网关、安全组、备份定时、告警值守和生产发布由部署团队负责，开发交接提供配置模板/数据库工具/功能接口与未完清单。开发方仍需补完真实发送器和云存储一致性等代码工作，不能把代码未接线只归因对方没有环境。
