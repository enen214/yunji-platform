# 批量资讯导入格式与恢复指南

后台“资讯管理 → 批量导入”支持 UTF-8 JSON 文件和粘贴 JSON。两个入口进入同一个导入命令，每行复用手工保存时的分类、内容类型、关键词和生命周期校验，并在保存成功时发布。

```json
[
  {
    "title": "停电通知",
    "contentType": "NOTICE",
    "categoryName": "校园服务",
    "labelNames": ["后勤"],
    "keywordNames": ["停电通知", "供电安排"],
    "levelTwoContent": "<p>通知正文。</p>",
    "levelThreeContent": "本周末供电安排",
    "levelOneContent": "原始通知来源文本",
    "importance": 4,
    "hotDays": 5,
    "timeLimitType": "SHORT",
    "effectiveFrom": "2026-10-27 09:00:00",
    "effectiveTo": "2026-10-28 18:00:00",
    "pushEnabled": true
  }
]
```

板块、标签必须精确命中已启用字典；标签必须属于该板块。关键词按规范化全局词库复用，未存在时在成功行事务中创建。日期时间格式固定 `yyyy-MM-dd HH:mm:ss`，解释为 Asia/Shanghai；存储为 UTC。导入字段映射见 `ArticleImportService.map`。普通信息需要一二三级内容；通知二级必填；攻略按 LONG_IMAGE 内容类型检查。

一个批次最多500条、文件不超过5MiB。超限在任何条目处理前拒绝。服务执行60秒预算内可返回 `PARTIAL`；成功条目逐条提交，不能假设批次整体回滚。回执含 batchId、total、processed、successCount、failCount、failList（原序号/标题/原因）、createdKeywords、duplicatedKeywords、timezone。新关键词跨本批创建及本库复用时分开列出。用原始 `Idempotency-Key` 重试同一请求，可续做未处理条目或取得完成回执；相同 key 不同内容返回409。新 key 表示有意发起一个新批次，不提供标题去重/覆盖。

失败行修改内容后应选择“再导一次”，界面生成新请求 key；不要改原 key 的 payload。批次状态可通过 `GET /api/v1/admin/articles/import-batches/{batchId}` 查询，创建者隔离。候选只在批次收尾时统一生成，批内条目互不比较。

**不支持** Excel/CSV、预览、标题覆盖、草稿导入或异步大任务。示例数据仅供本地试验，切勿直接拿示例内容当生产资讯。
