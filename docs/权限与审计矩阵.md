# 权限与审计矩阵

服务端 `Actors` 是新业务最终边界；前端按钮按会话权限显示，但页面显示不替代 API 鉴权。STAFF 在每次调用查询当前用户、部门、角色、菜单权限；已签发 token 在授权撤销后也失去该操作权限。CUSTOMER 只操作自己的可见对象。公司框架的系统管理接口沿用首次基座鉴权，独立于客户会话。

| 领域 | STAFF 权限 | 数据范围/状态约束 | 核心审计 |
|---|---|---|---|
| 资讯 | article:read/write/review/publish | 作者/授权部门；非管理员审核人与作者分离；确切版本 | 创建修订、提交撤回、通过退回、发布下线、替换 |
| 目录 | catalog:manage | 当前租户；父子和公开引用；乐观锁 | 创建、修改、撤下、别名、黑名单 |
| 活动 | activity:manage | 当前组织、表单版本、容量事务 | 配置、报名、取消、候补晋升 |
| 评审 | review:manage/decide | 评审组织范围；确切申报版本；材料私有 | 草稿、提交、撤回、评审决定 |
| 资料/附件 | resource:manage/file:manage | 当前发布关系、主体绑定单次票据；无引用才回收 | 配置、版本、下载票据/结果、回收 |
| 提醒 | notification:manage | 规则版本、账户状态、内容可见、额度预占 | 规则/取消、发送尝试、额度账本、UNKNOWN 核实 |
| 运营/反馈 | operation:manage/engagement:manage | 不可变协议同意版本；反馈/举报自身归属 | 配置、同意、解决/驳回 |
| 分析 | analytics:read | 用户汇总不提供身份行明细 | 聚合、写入事件 |
| 审计/导出 | audit:read + 独立 yunji:export | 导出还要求数据集领域权限；上限 5000 | DATA_EXPORT 和幂等成功审计 |

表内领域权限统一带 `yunji:` 前缀。普通初始角色默认没有 V17 新增 `yunji:export`；授权由管理员明确配置。新业务写 API 的成功回执、HTTP_WRITE 审计和业务结果同事务提交；已认证且进入事务的失败写入由独立事务记录 HTTP_WRITE_REJECTED，仅保存路由、请求哈希、状态，不保存请求正文或凭据。

身份登录/退出不走业务幂等切面。客户成功登录/退出由身份服务记录 CUSTOMER_LOGIN/CUSTOMER_LOGOUT；STAFF 使用框架登录日志。匿名身份失败、格式校验尚未进入业务事务的拒绝和网络请求日志不是业务对象变更审计，按安全访问日志处理，不能虚构不存在的操作者。

反向验收涵盖跨客户、跨主体、撤权后的旧会话、创作者不能发布/管理目录/导出、私有材料、单次票据及公开 DTO 字段过滤。C 端替换由用户明确确认，浏览/曝光不会变成已读。最终人员和组织角色矩阵由接收团队确认，不将合成账号作为正式用户。
