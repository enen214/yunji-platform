# 平台接入设计与验收

本文件适用于独立重制工程。C 端以 `apps/client` uni-app 为唯一源码，H5 和小程序均从这里构建。2026-10-22 已接入真实微信身份与可选手机号授权，指定旧项目的应用凭据经用户授权复用并通过官方凭据检查。流程与测试步骤见 [微信手机号登录专项交接](微信手机号登录接入与验收-20261022.md)。尚无真实用户原生授权端到端、绑定、消息送达或真机验收结论。本地合成授权不会成为正式授权。

## 已完成的可离线部分

`notification/infrastructure/ProviderProtocol` 实现发送响应分类、回调 SHA-1 签名/五分钟时间窗、AES-CBC/PKCS7 解密、接收 AppID/CorpID 校验和禁用外部实体的 XML 解析。畸形响应、未知错误码、HTTP 非成功响应和企微部分接收人失败归为 UNKNOWN，避免盲目补发。只有明确的供应商拒绝结果进入可重试或永久失败分支。

`ProviderHttpTransport` 提供小程序订阅消息、公众号模板消息、企微消息的固定官方 HTTPS 端点、有限 token 缓存、轮换失效、连接/请求超时、响应体上限和不跟随重定向。它不自动重试 POST，不打印凭据，不授予绑定或额度。JUnit 使用只监听回环的合成 HTTP 服务测试缓存、单次发送和重定向冻结；测试没有发送真实消息。

这些协议和传输代码尚未接入生产账本。生产 `NotificationService.tick()` 仍返回 503；未收到应用、模板和接收主体信息前不安装正式调度。不能把已有传输类说成完整平台通知集成。

## 接收团队先确认的非密钥信息

| 通道 | 信息 | 对实现的影响 |
|---|---|---|
| 小程序 | AppID、运营主体、测试账号、订阅模板 ID、各字段语义/长度、一次性或长期模板资格、合法域名 | 登录身份、授权提示、模板映射、有效额度和落地页面 |
| 公众号 | 独立 AppID、服务号资格、消息能力、关注/取关事件、同主体身份关联政策 | 绑定证明、授权策略、回调接收应用和接收人映射 |
| 企业微信 | CorpID、AgentID、自建应用范围、测试成员、身份关联方式、回调 URL | UserID 绑定、可见范围和消息权限，不能拿小程序 openid 当企微 UserID |
| 部署 | HTTPS 域名、平台 IP 白名单/回调条件、出口策略、时间同步 | 外网连通、合法域名和签名时钟 |

密钥由部署团队放入受限环境文件；不要贴聊天或提交 Git。AppSecret、企微 Secret、回调 token 和 EncodingAESKey 分用途管理。不沿用旧 demo 的身份、域名、整体配置或 SQL。本次明确授权的微信 AppID/AppSecret 是局部配置例外，只在受限私有配置中使用；不意味着其他通道也可沿用。

## 接线步骤和事务边界

1. 建立版本化的通道配置和模板字段映射。模板 key `CONTENT` 必须映射到已核准用途，不猜测字段或使用通用营销模板。
2. 明确每个绑定/授权事件的可信来源。客户 `requestSubscribeMessage` 的接受结果是客户端报告，不能把任意客户端 POST 当作供应商已授予的额度。正式模型应记录报告来源和发送拒绝纠正，长期/一次性消息分别计算。
3. 回调先限制字节数，再验签/检查时间窗、解密和接收主体，再解析事件。签名验证必须包含密文，不能仅对明文验签。回调业务事件按 provider/app/event ID 持久去重；没有稳定 ID 时采用含事件类型、主体、时间及内容哈希的明确去重规则。
4. token 在服务器缓存，不能交给 C 端。凭据错误码使缓存失效；重取 token 后只有明确未受理的请求才可按持久尝试策略重试。
5. 调度器先短事务领取任务、预占额度和记录 SEND_STARTED；事务提交后调用供应商，再短事务写结果、提交/释放额度。不能把慢 HTTP 放在持有整批行锁的本地模拟事务里。
6. 领取任务使用数据库租约、到期恢复和 `FOR UPDATE SKIP LOCKED`。崩溃发生在 SEND_STARTED 后而结果未落库时转 UNKNOWN；不能把所有过期任务重新当 PENDING 发送。
7. UNKNOWN 保留预占并等待可追踪回执/人工核实。不存在供应商幂等保证时，不承诺 exactly-once；人工核实需记录证据、操作人、时间和结论。
8. 后台再开放正式调度开关和健康检查。缺配置、缺绑定、无额度及内容撤下分别显示明确状态；不调用 LOCAL_FAKE。

## 接入完成后必跑的真实验收

使用独立测试应用和受控账号：正确/过期/重复登录码，AppID 不匹配，授权拒绝、一次额度和长期资格，关注/取关/解绑，多应用隔离，模板字段错误，凭据轮换，合法域名和出口失效，重复/伪造/过期回调，发送超时、进程崩溃、部分接收人失败、UNKNOWN 冻结、证据核实、限流恢复，以及取消规则/内容下线后不再发送。

每条记录供应商 request/message ID、脱敏日志、规则/任务 ID、开始/结束时间和结果。填写 `reports/platform-acceptance.json` 时必须附实际案例和当前源码指纹；仅填写 `status=PASS` 无效，不得作为发布证据。
