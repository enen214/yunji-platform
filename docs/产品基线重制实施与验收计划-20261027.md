## 4. 实施顺序与架构约束

### M1：先稳定内容命令，再接更多入口

手工创建、批量导入调用同一领域命令，统一做分类、内容类型、生命周期、关键词、状态与审计。不得另写一套导入 SQL 绕过领域校验。

取消内容审核和业务版本时，必须完整盘点：正文存储、资讯详情、阅读记录、关注、更替、通知变化、投递记录、缓存快照、前后端类型、契约生成与测试夹具。不能把旧版本表改名后继续向用户提供版本业务，也不能删除仍在被查询的表。

评审提交快照、文件版本、数据库迁移版本、乐观锁和审计不是业务内容版本，分别保留。单角色不等于任何客户都可以调用后台；员工身份校验和文件对象访问边界继续有效。

更替分“候选—确认/忽略—迁移关系—结束旧文—用户感知”。候选只提示，不自动替换；事务与锁顺序统一，防环、防重复确认，链最长 32。新文和旧文都要通过允许的生命周期校验。

### M2：排序与可见性独立

先做准入和生命周期过滤，再决定强加/紧急/置顶优先级，最后计算普通乘法分数并使用稳定排序键。筛选、排序、可见性不可混成一个任意大加分。

曝光、已读、当天冷却由服务端持久化；端上只提交符合条件的事件。固定时钟测试跨日、时效和热点边界，避免测试依赖机器恰好在某个时间段。

搜索快照冻结排序但每次读取仍核验下线/删除；服务端快照有资源上限和清理策略。不同结果场景分别定义“已读是否排除”，热搜不套首页排除规则。

### M3：统一用户关系与消息变化

关注不自动开启提醒；提醒成功设置时自动保证关注。取消关注可选择保留或关闭相应提醒。事务失败不得只保存其中一半。

盒子三栏统一聚合与去重，不由前端各查一份后碰运气去重。多标签小盒子可重复展示同一资讯，但必须共享该用户的全局阅读、曝光状态。

日常企微与即时订阅保留授权、内部状态、幂等及故障处理。隐藏用户投递结果不删除内部诊断。已建企微任务是否可撤收件人、任务最终如何确认，必须以真实 API 能力决定。

### M4：导入作为可靠运营工具

预检 JSON、大小、条数，再逐条独立事务。批次需要标识、内容摘要、执行结果、创建人和状态；网络断开后可以查询结果。同一幂等键不同内容拒绝，同一键同内容返回已有批次结果。不同键允许有意重复导入，不做标题覆盖。

业务校验、关键词建立和关系创建在单条事务内；失败回滚不留下半条内容。整批结束后统一生成候选，排除本批内部互比；批次断开/重试后仍可补偿执行，候选有唯一约束。

500 条、5 MiB 是初始预检上限，60 秒是性能与超时策略，不是已提交内容可神奇整体回滚的保证。满量测试后如需调整必须记决策，不能无说明放宽。

### M5：活动、文件和管理端收口

活动配置引用全局文件与评审项目；不再以学校组织作为创建前提。C 端去掉本期不要的独立资源、插件、考试、评审入口及可达旧路由，不仅隐藏首页按钮。

文件库支持文件与版本、活动引用、启停和安全下载。生产存储采用微信云存储适配，服务端签发临时链接，不向 C 端暴露 fileID。无资源时允许明确的本地测试提供者，但禁止生产配置悄悄退回本地模拟。

后台菜单后端下发，单一运营角色；基础账号体系、身份隔离、并发控制与必要审计保留。首期不暴露复杂角色/组织/数据范围 UI。

### M6/M7：交接必须可复现

首次安装提供 schema/seed；升级继续有迁移版本与校验，不改已发布迁移历史。初始管理员凭据通过部署输入或生成，不给生产通用固定口令。测试演示数据另行导入且可不导。

前后端与数据库必须配套升级。破坏性切换前有备份、导出核对、回退条件；不能声称新增/删列后只换旧程序包就能安全回退。

## 5. 验收证据规则

每条本期要求记录：实现文件、接口/页面、测试场景、结果、报告路径和对应源码指纹。拒绝以“页面存在”“HTTP 200”“有测试文件”替代业务验收。

验收包括正常、边界、权限、冲突和失败恢复：

- API：新发布、字段必填、生命周期、候选确认、并发词条、关系迁移、批次重试、错误回执。
- 浏览器：真实管理操作、C 端各入口、三栏去重、曝光已读、非热点空态、加载失败与返回行为。
- 构建：后端 verify、管理端类型/构建、C 端类型/H5/微信小程序构建。
- 运维：干净安装、重复初始化保护、升级备份恢复、配置缺失时明确失败、模拟能力不能在生产误开。
- 外部能力：微信/企微/云存储真实联调、开发工具/真机、Linux amd64 目标部署分别标记，未做不写通过。

旧测试中送审、审核通过后发布、阅读按内容版本重置、取消关注必停提醒等断言已与新需求冲突，应按新需求替换，并记录废弃原因。身份、对象权限、防环、事务、幂等、故障恢复等仍有效测试必须保留或加强，不能为追求全绿删掉。
