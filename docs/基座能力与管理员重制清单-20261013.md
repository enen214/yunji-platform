# 基座能力与管理员重制清单

本清单用于回答“继承的是哪些后台能力”。原版管理员前端文件缺失，不声称恢复原版；当前 Vue 管理端独立重制，已有公司后台接口按权限使用。业务源码不从 gld0.5 提取。

| 能力 | 管理端入口 | 实际边界 |
| --- | --- | --- |
| 工作人员、角色、部门、菜单 | 系统管理 / 账号与权限 `/system` | 工作人员 STAFF 域；继续使用公司基座的权限能力，客户 CUSTOMER 另表另会话 |
| 岗位、字典类型/数据、参数、公告、客户端 | `/foundation/post`、`dict`、`dict-data`、`config`、`notice`、`client` | 管理员受控页面和相应基座接口；不是面向客户开放的 CRUD |
| 缓存、在线人员、登录日志 | `/foundation/cache`、`online`、`login` | 现有管理员只读/治理范围；操作权限由服务端最终判断 |
| 操作审计 | `/audit` | 新业务 write/导出及强提醒人工核实/补提留痕；核实证据不包含密钥 |
| 客户目录 | `/customers` | 与系统工作人员分离，不给客户套部门角色；客户状态由新业务接口管理 |
| 板块标签关键词 | `/catalog-tree`，保留 `/categories`、`labels`、`keywords` | 联合工作区和显式多对多编排；关键词保持全局身份；停用不伪装删除 |
| 提醒运营 | `/reminders/*` | 配置、服务端分页规则/记录、全量统计、补提核实；生产真实供应商尚未接线 |
| 多租户与套餐 | 未作为产品入口启用 | 当前固定公开租户，不能仅启开关宣称支持完整租户隔离 |
| OSS | 未作为新业务存储能力启用 | 私有本地文件及下载鉴权是当前方案，切换对象存储需专项设计 |
| 代码生成、工作流、公司分布式任务中心 | 保留的基座源码不等于运行包启用 | 当前交付构建仅 agri-admin 所需 reactor；新提醒使用独立调度和数据库防重 |

权限基线：`apps/admin/src/permissions.ts` 管理页面入口；`Actors` 和各服务的 require 检查承担服务端授权。菜单隐藏只是体验处理，不能代替接口拒绝。创作者能创建资讯，不自动获得分类/提醒运营权限；审核员能进入材料评审，不获得创建资讯能力；管理员核实强提醒须明确证据。

基座配置和框架版本本轮未更换。测试覆盖沿用 API/真实页面固定场景，新增后端接口另有专项；“代码中存在”不等于每个基座组合都已穷举验证。源文件可追溯至 `docs/decisions/framework-source.json` 与本轮 `reports/provenance.json`；精确/去空白指纹检查不证明无限意义的无抄袭或完整质量。

新增管理员页面步骤：在服务端定义 realm 和所需权限；定义明确 DTO 与审计；在 main.ts 注册路由及 section；在 permissions.ts 加页面映射；在 App.vue 对应分组添加入口；使用真实角色验证“可见且可用”与“直接访问仍拒绝”。新增功能需要业务模型时追加 V23 及以后迁移，不改已发布历史 SQL。
