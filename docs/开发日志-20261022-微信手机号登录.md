# 开发日志：微信手机号登录

## 范围与决定

- 用户要求直接沿用旧项目的微信登录能力。核实旧客户端 `getPhoneNumber + uni.login`、旧服务端 `jscode2session + getPhoneNoInfo`，确认其具有真实手机号授权流程。
- 只沿用官方协议及获授权的应用配置；没有复制旧业务源文件、表和登录策略。旧版捕获手机号异常后继续成功、日志输出手机号和授权码的行为不沿用。
- 用独立真实入口 `/api/v1/auth/customer/wechat/native` 消除 local 环境把微信授权码当合成码的问题；保留既有接口兼容性。
- 手机号为可选授权；不按号码合并账号、不保存完整号码、不影响公开浏览，也不生成强提醒授权。

## 实施记录

- 实现固定官方端点、AppID 校验、openid 换取、非强制刷新 stable token、获取手机号与 watermark 校验。短事务创建/更新新工程账号，保存脱敏显示值并签发原客户会话。
- 增加体积上限、超时、不跟随跳转、敏感异常脱敏、失效 token 缓存清除。不自动重试单次 code 或手机号调用。
- uni-app 两个登录入口共用 helper，接入原生授权按钮、协议同意门槛、普通微信登录、重复操作互斥和离页响应作废。
- 增加工作台显式私有配置参数、微信专用构建脚本。专用包写入忽略目录，不改追踪中的 manifest 或标准构建产物。
- 原配置 AppID 与前端匹配；密钥文件仅本机受限保存，已核对 Git 忽略。官方 stable_token 检查通过，仅凭据检查、无手机号调用、无消息发送，未保存返回 token。
- 新增后端协议/边界和前端异步行为测试，加入 API 负向用例和本地门禁。首次构建发现测试类漏导入 Actors，已补导入并重新构建；不隐藏失败记录。首轮 API 中新增两项参数校验用例误写预期 400，实际框架统一返回 422；按既有契约修正用例，保留首轮报告到忽略的运行目录并完整重跑。
- 更新专项交接、当前状态、部署/操作/二次开发和平台说明。真实微信用户授权测试待开发者工具/真机操作；不把凭据通过写成平台通过。

- 初次浏览器五套143项和运维20项通过后，复核修正短号码脱敏边界（不足10位仅保留首位/末两位），增加协议测试。因为源码指纹改变，重新执行构建和完整验收，旧通过报告不冒充最终版本证据。
