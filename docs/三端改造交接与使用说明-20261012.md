## 需求核实结论

原生 tabBar、双列资讯、插件教程原本存在；原迁移已到 V19。资料、插件、轮播、标签、公开协议等空列表由运营发布内容，不填充虚假生产资料。系统基座接口继续使用 `/system/**`、`/monitor/**`，新业务继续使用 `/api/v1/**`。

本轮补充的是页面结构与真实数据缺口，不恢复旧 demo 业务实现。管理端允许复用字段控件，但运营模块的列表、新建、编辑、详情有独立路由，不再把所有操作压入列表上的弹窗。

## 1. 客户端使用

同一份 `apps/client` uni-app 源码编译 H5 与微信小程序。底部四项为主页、信息盒子、板块、我的；服务、活动报名、学生申报与资源下载仍可从板块/我的进入。

### 搜索与发现

- 首页搜索入口进入独立搜索页。未搜索时显示个人搜索历史、真实热搜。游客历史只在当前设备；登录历史由服务器按账号保存，最多 20 项，可清空。两种历史不自动合并。
- 筛选在底部弹层：类型单选、板块单选、标签多选。不同维度取交集；多标签取并集。学校/组织保留首页独立筛选。
- 默认搜索当前有效和待生效内容。勾选“启用过期历史信息搜索”才包含过期内容；任何时候都不显示草稿、撤下、私有或删除内容。旧查询接口的既有行为保持兼容，新页面使用 `/articles/search`。
- 查询快照有效期 10 分钟，最多 10,000 条。变更条件后重新查询；翻页的 cursor 必须匹配原查询、账号、分页大小和 snapshotAt。快照过期按提示重新搜索。
- 空结果可登录提交“缺失信息申报”，进入既有反馈工单流程；不能把未公开数据自动当作缺失。
- 板块页显示已发布可见资讯数；进入板块可以查看标签，再进入标签和关联关键词。关键词关联来自已发布文章，不人为发明“词属于某标签”的永久关系。

### 关注与信息盒子

“推送信息”显示板块和标签关注；“关注更新”显示单篇资讯与关键词关注；“关注信息更替”保留原内容更替通知。关注更新是站内内容状态，不等于已发送微信消息。

管理关注、选择推送标签、搜索关键词均为独立页。选择父标签不隐式关注所有子标签。暂停盒子推送不取消关注；隐藏不删除数据。取消关注只作用于当前账号。

卡片左右滑动超过阈值可标记已读，也有“标记已读”按钮。提交的是卡片显示的确切文章版本；服务器发现版本已更新时拒绝标记，用户必须打开新正文再确认。

首页“关注更新数”按未读资讯去重，排除隐藏/暂停盒子；今日推送按 Asia/Shanghai 当日 `SENT` 投递记录计数。一个每日摘要投递计一次，不等同摘要内资讯条数。

### 我的、活动与资源

个人中心是功能入口。收藏、浏览历史、个人资料、报名、申报、反馈各自独立。收藏和历史支持单条删除及确认后清空；注销账号会清除新增的搜索历史/活动收藏并停用会话、关注与提醒。

活动总览提供全部/收藏两项，收藏不等于报名；活动详情继续使用容量、候补、动态表单和取消报名的现有闭环。当前活动模型没有独立活动附件关系，因此不显示虚假的“活动资料下载”；资料包和插件文件仍从资料模块下载。

资源页保留科目、年级专业、考试日程、资料包和插件发布。运营应先上传受控文件，再发布版本并关联已公开的教程文章。客户端显示服务器 SHA256 信息，不能表述为客户端已经重新计算并校验全部下载字节。

### 强提醒

主页分“定时与摘要”“即时提醒”两项。新增和编辑在独立页面；具体时间与每日发送时间、静默时段按每条规则保存。列表可暂停/恢复、取消、改为即时，修改仍受版本冲突保护。

强提醒设置页说明规则范围，通道与授权页显示真实绑定/额度状态，发送记录页保留历史投递。公众号不再作为新规则可选通道，历史记录显示“已退役通道”。用户保存规则不代表已获得平台发送授权。

本地显示“本地模拟验收”；正式平台接入未完成时显示待接入。没有 AppID、模板、企微应用和实际接收账号时，不提供假授权按钮或伪造绑定成功提示。

## 2. 运营后台操作

导航分内容运营、活动与资料、提醒与企微、客户与统计、系统与监控。面包屑显示当前模块；权限由后端再次检查。

### 板块、标签和资讯

1. 在板块管理维护板块；学校/组织独立维护。分类与标签不是组织身份。
2. 在板块标签新建标签，填写唯一归属板块、可选同板块父标签、排序和状态。已建标签不能迁移板块；另建目标标签再修订文章。循环父子引用会被拒绝，父链最多八层。
3. 新建或修订资讯时选择唯一板块、该板块下的多个标签、可选关键词和组织。新增类型 `NOTICE` 用于通知；`BASIC/GUIDE/ACTIVITY/REVIEW/RESOURCE` 保留。
4. 标签关系进入不可变版本快照，仍需提交、审核、发布后才对客户可见。创建草稿或编辑目录不会直接改写已发布文章的标签关系。
5. 更替操作继续在资讯详情确认目标，保留现有自动迁移关注和提醒、保留历史与不增加授权额度的规则。

通知管理、通知历史、信息更替和推荐策略提供对应入口，使用现有文章版本与排序体系，不另建重复“通知文章库”。通知历史包含修订审核历史，可追踪何时生效/结束。

### 列表、表单与统计

运营维护模块使用独立 `/模块/new`、`/模块/编号/edit`、`/模块/编号` 路由；返回列表不会保存未提交内容。旧运营列表接口仍有 100/200/500 等上限，页面明确显示已加载数量；其搜索与分页只针对已加载记录，不能当作全库搜索。客户用户目录和基座列表使用服务器分页。

客户用户目录仅超级管理员可访问，仅显示业务编号、昵称、组织、状态和时间；不提供 OpenID、UnionID、令牌或身份合并。没有业务依据，不增加任意封禁、假授权或个人画像编辑操作。

数据看板、内容统计、行为统计、用户概况使用真实聚合口径。行为日报按 UTC 生成；首页今日发送按上海时区，两个口径不能混用。用户概况只显示有效/注销账号和访问总量，不推断性别、收入等未采集信息。

提醒规则、发送记录、设置说明、模板接入、统计、监控和企微页面分别组织。统计从加载的账本行按投递编号去重，页面明确样本上限。未知结果仍从提醒账本提供供应商凭据后核实，不能无证据重发。

### 基座系统与监控

新增接入岗位、字典类型/数据、参数、公告的原生受权接口及表单；客户端配置只读，避免误改本应用登录标识。缓存、在线工作人员、登录日志使用原基座接口；在线列表不把登录令牌显示到表格。

本轮不启用以下项目：

| 项目 | 原因与后续边界 |
| --- | --- |
| 多租户/租户套餐 | 新业务固定 `000000`；直接开放框架租户开关会造成“菜单支持、业务未隔离”的错误承诺，需要专项隔离设计和测试 |
| OSS 配置管理 | 新业务文件私有目录、受权票据、引用保护和回收已成闭环；改成 OSS/S3 必须实现存储适配与权限验收，不能仅增加上传页面 |
| 生产任务调度 | 当前提醒真实供应商及回调未接线，不启动空调度器或无效任务面板；生产团队已有运维系统可独立使用 |
| 企业微信自动/手动真实发送 | 接收身份、模板/用途、应用权限、签名回调和防重验收需资源到位后实现；本地账本不代表完成 |
| 工作流/代码生成/旧静态 mock 页面 | 明确不纳入本次 |

## 3. 数据与兼容性

增量迁移 `V20__discovery_labels_and_search.sql`，保留 V1–V19 校验和。新增 `content_label`、`article_label_rel`、`customer_search_history`、`activity_favorite`；扩展 `user_follow` 的类型约束为含 LABEL。迁移停用公众号规则，保留历史账本。

旧文章快照没有 `labelIds` 时按空列表解释；新版本带入标签。不得重新编辑已应用迁移以修复环境；MySQL DDL 的失败恢复继续遵守原交接书。

新增 HTTP 入口及字段见生成后的 `contracts/openapi.yaml`、`contracts/endpoint-matrix.json`。公开读请求不写搜索历史，历史写入使用登录用户接口，避免 GET 被预取或爬虫误计为搜索。

没有旧数据迁移。如另行委托，只迁经过映射验证的数据，不能将旧 SQL 表结构或 demo 代码导入本工程。

## 4. 构建与交接

目标已经确认 Linux amd64、Docker 可用，保留当前后端环境变量和依赖配置。新增容器操作见 `deploy/docker/README.md`。本机无 Docker，不提供虚假的镜像验证结论；目标数据库和 Redis 的地址、版本、权限、附件路径由他们提供，生产配置和上线由生产团队负责。

开发机命令：

```text
python scripts/build_acceptance.py
python scripts/acceptance.py
python scripts/browser_acceptance.py
python scripts/operations_acceptance.py
```

这些命令创建隔离空库和纯合成数据。全部成功后才更新交付门禁；旧报告日期和旧源码指纹不能用来证明新改造通过。微信开发工具/真机和 Linux 容器仍须单独签收。

本地手动试用使用 `python scripts/workbench.py start`，H5 `http://127.0.0.1:5173`、管理端 `http://127.0.0.1:5174`；命令运行成功之前这些地址不代表已启动。一次性客户登录码通过另一个终端的 `python scripts/workbench.py code alice` 获取。
