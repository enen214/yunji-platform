# 实施计划与交付纪律

本工程从公司框架净化基线开始，业务只在 yunji-content 编写。样本只作需求证据，不引入旧业务源码、数据库或兼容接口。

1. 完整基座：官方系统表与配置、MySQL/Redis隔离启动、框架STAFF登录、CUSTOMER隔离认证、迁移历史和权限测试。
2. 内容闭环：目录维护、不可变修订、精确版本审核与发布、部门数据范围、公开检索、审计及outbox。
3. 用户闭环：资料、协议、订阅、收藏、历史、已读、举报与反馈；用户身份只能来自服务端会话。
4. 通知闭环：规则、调度、数据库额度账本、通道适配、重试与UNKNOWN隔离。真实平台验收独立列出。
5. 文件及业务：受权下载、活动容量/候补、评审提交版本、科目/资料/考试/插件、运营和统计。
6. 前端：管理员/创作者工作台、用户完整导航与表单；契约统一、错误可恢复。
7. 验收：从空库启动，正反例、权限、重复请求、并发、故障、迁移重跑、备份恢复及前端构建；生成真实报告与交付门禁。

每个用例必须有执行证据。部分实现不得标记全功能通过，构建成功不得冒充运行验收。本地模拟通道不得标记真实平台通过。候选需求 AUTH-05/CAT-06 不擅自扩展范围。
