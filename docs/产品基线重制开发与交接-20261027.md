# 产品基线重制开发与交接

版本：`feature/product-baseline-rebuild-20261027` 候选；生成日期 2026-10-27。本文按实际源码与本轮报告更新。尚非生产发布批准。

## 业务规则与边界

C 端是 uni-app 单一源码，产出 H5 与微信小程序；后台是独立 Web。内容由板块、至少一个板块标签、至少一个全局关键词组成；保存即发布，纠错原位保存且不触发新发布提醒，重大变化另建内容，经人工确认更替后迁移关注/强提醒并保留旧文历史详情。下线和删除不可公开访问。具体工程取舍见 [产品基线工程决策](decisions/产品基线工程决策-20261027.md)，234条逐项证据见 [机器台账](spec/product-baseline-20261027.json) 与 [人读台账](spec/产品基线逐条台账-20261027.md)。

列表先做生命周期/热点/已读准入，再按强加、紧急、置顶、普通排序；普通评分使用重要度、热点剩余日、时效半衰、关注和曝光乘数。曝光须滚动进入可见区域并持续满足前端观察条件，后端按用户资讯30秒去重、每日三次降权/冷却、累计九次隐式已读。搜索使用用户绑定快照分页，但每页仍复核当前可见性。盒子为更替、关注更新、推送三栏实时计算，按优先级去重；普通关注与强提醒分离。

批量导入和格式约束见[导入指南](批量导入格式与恢复指南-20261027.md)。活动引用全局文件版本及评审项目。后台只有统一运营角色，菜单由数据库返回，服务端仍验证工作人员主体。登录沿用已接入的微信登录代码；真实 AppID 可用性与真机授权不计本地模拟通过。

## 模块与接口入口

后端位于 `backend/agri-modules/yunji-content`：article/catalog/discovery/subscription/engagement/activity/review/resource/notification/analytics/identity。后台页面在 `apps/admin/src/views`，C端页面在 `apps/client/src/pages`。数据库迁移 V24 产品模型、V25 全局文件、V26 热点软归档；迁移不可改写。运行契约见 `contracts/openapi.yaml` 和实际接口矩阵。`ResourceController` 的旧资源端点已从 Spring 注册，不代表所有历史 Java 类型/表均已删除；它们仍被授权框架外键或审计读路径使用。

机器台账中的旧 demo 仅作为旁路研究材料；本项目验收从公司允许的 cis4j 框架 schema 开始。来源比对报告只能说明检测到的完全/空白归一匹配情况，不能证明重写代码没有任何思想或片段来源，也不能代替许可证审查。

## 开发、启动与验收

依赖与命令见[本地使用说明](本地开发与验收使用说明.md)。`python scripts/workbench.py start` 启动默认隔离演示，C端 `http://127.0.0.1:5173`、后台 `http://127.0.0.1:5174`；演示数据仅在随机 runtime 数据库。默认客户本地码通过另终端 `python scripts/workbench.py code alice` 获取；不得把这种路径暴露到生产。

复跑本轮门禁：设置本机 Java 21/Maven/MySQL 工具变量后执行 `python scripts/product_candidate_acceptance.py`。报告分别写入 `reports/build.json`、`product-baseline-acceptance.json`、`browser-product-baseline.json`、`workbench-demo.json`、`operations.json`、`install-snapshot.json`、`client-compat.json`、`wechat-login.json`、`provenance.json`。最后执行 `python scripts/product_release_gate.py`，检查指纹、测试清单、迁移快照和文档是否都为当前版本。不同测试按顺序启动和关闭隔离服务，不与人工工作台或其他验收复用数据库。

本轮最终报告本地 API 123 项、浏览器 14 项、构建6项、运维恢复演练20项、安装快照6项及兼容/登录/来源核查的最终数字，以实际运行报告为准。发布门禁强制 `releaseEligible=false`：真实微信/企微、云存储、Linux amd64 Docker、微信开发者工具/真机和安全发布审查仍未在外部环境验收。

## 目前明确的未完成项

- 提醒规则、队列、事故检测、管理员监控和本地模拟已实现；真实 WeChat/WeCom 传输没有接到 ReminderWorker，自动调度目前会在生产 fail-closed。企微按业务设计需先建任务再由员工在企微后台一键发送，当前也没有真实 API 调用实证。
- 文件库能本地管理版本，生产适配器实现云上传及短期下载 URL 的协议调用，但上传会先落本地文件形成副本，尚未做真实云环境端到端和一致性补偿。此项不应描述为云存储已完全交付。
- C 端头像字段目前读取/占位展示，没有头像选择和上传；每个活动“前端独立页面”要在实际活动设计确定后开发，现有页面是通用专题/活动承载模板。
- 7-17有数据库事故查询和日志告警节流，没有真实告警渠道。每日自动备份需生产团队按备份系统或安全停写窗口配置；仓库备份命令要求应用停止，并非定时任务。
- 规则3-23、4-07、6-18、10-09等尚需专项交互/负载/实际业务实测；12-03规格写客户应得403，当前统一客户缺乏员工身份的流程回401，已实现拒绝访问但状态码有差异。13-02规格说全新表结构，实际保留公司框架和迁移链，只新建业务模型，不能宣称彻底重建了整套表。
- 规则1-19～1-22只在导入文档被引用，收到的文件未提供其内容。完整规则按234条登记，不猜写缺项。

## 安装/升级/回滚

空库安装快照和工具见 [database/install/README.md](../database/install/README.md)。生产优先 `database_ops.py initialize` 从不可变迁移新建库，再 `bootstrap` 设置独立管理员口令。升级先停止写入、备份数据库和附件，再 `database_ops.py migrate`；不要对已有库导入安装快照。回退需恢复到新库/新附件目录并配套对应应用版本，MySQL DDL 失败不可盲目重跑。

V24 的实际数据影响包括旧重要度最小调整为1、按原热点权重初始化截止日、结束旧CATEGORY关注；新增类型字典、候选/导入/曝光/搜索日志及统一菜单。V25新增全局文件/引用/下载，不会自动把旧资料包变成文件库；V26只增加软归档字段与索引。运维演练证明迁移工具和恢复过程，不证明任意旧业务状态都能自动转换。已有V23测试内容若不符合一个板块/必填标签等新约束，需人工核对或按用户“不迁旧数据”要求另建新库；不要直接将旧工作台库当生产库。

目标 Linux 配置沿用后端现有 Java21/MySQL8/Redis7 设计并以 Linux x86_64 Docker 为目标；本机 Windows 回环不是目标容器验收。生产变量模板为 `deploy/api.env.example`，密钥只放权限受控文件或部署密钥系统；平台未配置时必须保持相关功能禁用或显式报错，不允许回退本地模拟。当前逐步操作见[产品基线操作与接力验收手册](产品基线操作与接力验收手册-20261027.md)，基础部署模板和历史说明见[部署团队交接操作书](部署团队交接操作书.md)。

## 交接建议

工程候选需先由负责人 review 本文未完成项和 `reports/product-release-gate.json`，随后可提交到研发分支供接收团队部署试验。交接团队应报告镜像摘要、迁移版本、健康探针、回环登录/管理操作、备份恢复演练和未接平台项。不得把“可推送候选”说成“完整完工”或“生产就绪”。
