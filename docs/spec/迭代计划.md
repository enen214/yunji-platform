# 迭代计划

按一人主程或小团队可执行的顺序编排。每个迭代都必须有可运行产物和验收证据。

## 第 0 周：冻结输入

- 委托方回答 `需求基线-v0.1.md` 的 A1–A6。
- 轮换已暴露凭据，拿到新的 AppID/域名/对象存储责任人。
- 冻结 `openapi.yaml` v0.1 和 `V1__core_schema.sql`。
- 用脱敏数据建立本地库；建立新 git 仓库和 CI。

验收：任何开发者只凭 README 能启动 MySQL/Redis/后端骨架；`scan_secrets.py` 零命中；旧线上不可达。

## 第 1 周：基座净化与认证

- 从 `cis4j` 基座导出，不复制 hd0.5 的业务污染。
- 接入新业务模块和 schema 迁移。
- 配置 CORS 白名单、client_id、Bearer token、统一错误响应和 request_id。
- 完成 STAFF/CUSTOMER 会话边界；本地 mock 客户登录。

验收：后台 admin 登录不受影响；客户 token 不能调用 STAFF；未登录无法写互动接口。

## 第 2 周：目录与资讯读取

- 分类、组织、关键词 CRUD 和公开查询。
- 内容公开列表、详情、有效期和稳定排序。
- OpenAPI 生成客户端类型；H5 首屏展示真实接口数据。

验收：至少 1000 条种子内容下分页无重复；同分排序可复现；组织/分类过滤结果可解释。

## 第 3 周：内容工作流

- 草稿、版本、提交、审核、发布、下线。
- 后台列表、编辑器、预览、审核时间线。
- `@DataPermission`/等价 SQL 行级隔离和审计事件。

验收：创作者 A 不能读取/导出创作者 B；旧版本可回看；审核后的版本被修改时必须重新审核。

## 第 4 周：订阅与互动

- 关键词/内容订阅、订阅聚合流。
- 收藏、浏览、已读、分享、举报。
- 统一行为事件和推荐曝光冷却。

验收：重复点击幂等；清空历史不影响收藏和订阅；用户看到的推荐可解释。

## 第 5 周：C 端视觉与小程序

- 先完成 token、卡片、筛选器、空状态、错误状态。
- H5 完成首页、发现、详情、订阅、我的。
- 微信模拟器验证平台差异，接入微信 code 登录。

验收：H5 全流程可走通；模拟器无运行时错误；真机/体验版只使用备案 HTTPS 域名。

## 第 6 周：运营与迁移演练

- Banner、推荐位、协议页、举报处理。
- 编写旧表映射和脱敏导入脚本。
- 灰度部署、回滚、备份恢复、观测面板。

验收：从一份脱敏旧库可重复导入；失败行可定位；回滚到上一版本不丢审计记录。

## 后续门

只有当 MVP 埋点证明需求成立，且委托方确认资源后，才进入强提醒、活动、评审、资料包、插件和院系自助入驻。每个门都单独建表/接口/权限，不把新功能再次塞进资讯聚合服务。

## 每个 PR 的最低要求

- 关联一个验收项或 ADR。
- 迁移脚本、接口契约和权限码同步更新。
- 通过单元测试、接口测试和 `scripts/validate.ps1`。
- 不包含真实密钥、node_modules、target、dist、`.bak` 文件。
- PR 描述写清数据变更、回滚方式和未覆盖的微信平台能力。
