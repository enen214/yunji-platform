# 三端改造核实与实施决策

输入版本：2026-10-12 用户提供《三端改造需求说明.md》。本文件记录核查事实与实施边界；有歧义的甲方描述按当前契约和用户“专业判断优先、不得复用 demo”要求处理。

| 要求 | 当前证据/问题 | 决定 |
| --- | --- | --- |
| 原生 tabBar | 已存在；缺图标，名称为资讯/订阅/服务/我的 | 更新为主页/信息盒子/板块/我的，服务保留独立入口 |
| 首页 | 已双列卡片，有轮播数据和推荐；缺独立搜索入口、通知摘要 | 改善分页、轮播与通知入口；不把同高双列卡片误称单列 |
| 独立搜索 | 现有内嵌；服务端尚无完整类型/关键词筛选、过期开关 | 新增独立页；筛选需要服务端支持，不能筛当前一页冒充完整结果 |
| 板块/标签/关键词 | 分类有 parentId；关键词独立平面模型；需求引用的 2.4/2.5 不存在 | 保留目录树、组织和关键词独立维度；用户授权自主设计：唯一板块、标签树精确匹配、关键词跨板块独立；不复制旧表 |
| 信息盒子 | 已有 CATEGORY/FOLLOWING/REPLACEMENT、关注更替自动迁移 | 拆管理关注与关键词入口；已读绑定确切版本，滑动只作为便捷交互并保留按钮 |
| 资讯详情 | 当前类型为 BASIC/ACTIVITY/REVIEW/GUIDE/RESOURCE，非 info/notice/guide | 类型需显式映射；通知不能从标题猜测；保持原有五类功能 |
| 我的 | 当前同页收藏/历史/报名/申报 | 拆独立页，保留资料、反馈、协议、注销及现有事务操作 |
| 强提醒 | INSTANT/AT_TIME/DAILY 已有，公众号残留可选 | 拆列表/编辑/通道/记录；保留三种方式，退役公众号时保留历史账本 |
| 活动总览 | 服务页已有活动列表、活动详情报名/候补 | 独立总览；收藏映射须有真实关系，下载只展示已关联可访问材料 |
| 下载与攻略 | resource 已有插件下载和 guideArticleId；空列表不是缺功能 | 保留新实现，明确空态和运营配置；不造插件、教程、文件 |
| 管理端壳与页面 | 23 个平铺菜单；通用 Workspace 非所有模块独立页 | 分组菜单、面包屑、列表筛选/分页和明确功能入口；允许复用基础控件，拒绝旧业务组件 |
| 通知/历史/更替/策略/板块 | 多数是现有资讯、目录、排序与更替功能的不同视图 | 按现有领域提供入口与说明，避免新建重复业务域 |
| 客户用户管理 | 当前仅聚合，缺独立列表 | 以最小可见字段与工作人员权限设计，禁止导出微信标识或随意合并身份 |
| 精细统计 | 已有事件聚合、UV和用户数量 | 只展示真实采集数据及口径；无画像数据不推断敏感画像 |
| 企微管理 | 真发送/回调/调度未完成，无平台资源 | 明确接入与联调边界；有账本才展示记录统计，不仿造可发送按钮 |
| 监控与系统菜单 | 基座能力与业务控制器分别授权；不全是 /api/v1 | 按已有控制器和权限逐项核查；运维控制台不以业务页面绕过认证 |
| 多租户/OSS/任务调度 | 新业务当前固定租户、私有本地文件；不等同框架开关 | 不直接开放会破坏隔离的后台按钮，需专项设计；说明“不能仅补前端”的原因 |
| 框架错误页 | 旧页面无需迁回 | 新工程仍需正常 404/无权限/错误状态，不能以删除旧遗留为由去掉错误处理 |
| 工作流/代码生成 | 文档明确不恢复 | 不纳入本次 |
| Docker | 可用，但项目原生模板，现无容器配置 | 作为独立交付适配；保留后端现有变量和业务配置，目标架构已确认 linux/amd64；已新增 deploy/docker，目标机待验 |

已纳入且开始执行：前端导航/页面拆分、真实数据入口、必要契约补充、日志与交接文档、本地回环。待平台资源或专项架构的事项单独记录，不能把整份需求标成全部通过。
