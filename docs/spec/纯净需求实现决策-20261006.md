# 纯净需求实现决策

本文件把 `评估报告/甲方需求-纯净功能清单.md` 转成工程基线。需求原文中的口语描述不直接作为数据库字段或页面文案；系统只以这里的规则、接口契约和验收案例为准。

## 已纳入本期基线

| 范围 | 工程决策 | 验收方式 |
|---|---|---|
| A 内容库 | 统一使用资讯模型；摘要、正文、来源名称、来源 URL、内容类型和不可变版本共同组成一条资讯 | 创建、版本、发布、来源跳转和危险 HTML 清理 |
| B 分类 | 一条资讯必须且只能属于一个板块；关键词和学校/组织仍是独立多选维度；载体以内容类型和附件关系表达 | 管理端单选板块；服务端拒绝 0 个或多个板块；筛选交集 |
| C 生命周期 | 草稿、审核中、已发布、下线由版本状态机控制；生效起止时间决定当前可见和历史归档 | 发布、撤回、过期不进当前列表，历史接口可查 |
| D 属性 | 置顶、重要度、热点、新鲜度进入版本快照并投影到发布资讯；举报进入异常处理流程 | 权重范围校验、发布后排序、举报处理权限 |
| E 排序 | 关注提升 50、置顶 100、内容权重、热点权重、新鲜度权重×2，并对临近开始的活动加 `max(0,20-floor(hoursUntilStart/12))`；同分按发布时间和 ID 稳定排序；分页使用不可变快照 | 排序回归和并发快照验收 |
| F 盒子 | C 端分为板块推送、关注更新、更替推送三栏；真实外部发送仍受平台资源门禁 | 本地盒子、规则账本、供应商未配置时拒绝发送 |
| G 订阅 | 关键词、单条资讯、板块均可关注；盒子可隐藏；提醒独立于关注 | 三类关注 CRUD、跨用户隔离、未读摘要 |
| H 更替 | 管理端确认后旧资讯下线并记录关系；单条资讯关注和强提醒自动迁移到新资讯，用户在 C 端查看新资讯；历史和审计保留，授权额度不增加 | 替换链、环检测、自动迁移、历史读取和幂等验收 |
| I 内容 | 攻略、活动沿用资讯/活动领域模型；活动报名与资源下载已有独立权限和版本规则 | 活动、报名、资料包和下载闭环 |

## 明确不伪造完成的范围

- H3 同一事件的多资讯关联、I3 详情相关推荐、I4 词条浮动解释：需求清单明确标记未开发，本期保留产品待办，不添加无定义的假数据或假入口。
- B3 长图/文件的自动内容提取：只完成载体分类和文件关系；提取规则、OCR、版式转换需要甲方确认样本和准确率后立项。
- F2 企业微信、F3 微信订阅消息、公众号绑定：本地只验收账本、额度、幂等、重试和 UNKNOWN 冻结；没有独立 AppID、模板、企微应用及 HTTPS 回调资源时，生产发送保持关闭。
- I2 活动的最终展示形态：已实现活动领域和报名闭环，首页栏目呈现方式由运营配置；不把活动硬编码成固定频道。

## 本次工程变更

1. V18 迁移为资讯版本保存排序权重，并允许 `CATEGORY` 订阅类型；V19 增加解读/原始信息、载体、异常标记、盒子推送偏好和持久化更替通知，并索引行为事件。
2. 服务端强制每条资讯唯一板块归属；管理端改为板块单选。
3. 排序权重在发布时投影到资讯主表，公开列表按稳定综合分排序。
4. 订阅服务增加板块信息盒子和盒子类型，C 端提供三栏切换。
5. 合同模型、前端模型、浏览器验收同步更新，避免只改页面不改接口。

公开首页在无搜索、板块和组织条件时默认只取 `hot_weight > 0`；任一筛选或搜索会关闭热点限定。登录用户的无搜索列表曝光按 UTC 日期至少 3 次和 30 秒服务端计数冷却限制，匿名请求不按用户个性化。

## 交付门禁

本轮必须同时通过：后端单元/集成验收、管理端和 C 端类型检查、H5 构建、微信小程序构建、浏览器核心/扩展/闭环回归、来源与需求追踪检查。外部平台和目标 Linux 仍单独签字，不以本地合成数据代替。
