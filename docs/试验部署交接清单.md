本清单用于把研发阶段检查包部署到隔离的 Linux 预发布环境。它不是生产上线授权，也不允许连接旧库、导入旧 demo 数据或开启真实微信/企微发送。

## 1. 试验环境

- Linux LTS、JDK 21、MySQL 8、Redis 7、Nginx、Python 3.10+。
- 服务器只开放 80/443；API、MySQL、Redis 只监听内网或回环地址。
- 使用新的测试域名和 TLS 证书；不要使用旧站域名直接切流。
- 创建独立运行用户 `yunji`、独立数据库 `yunji`、独立附件目录 `/var/lib/yunji/files`。
- 试验库必须为空库；本包不提供旧数据迁移，也不允许导入 `database/fixtures`。

运行时直接使用包内 `artifacts`：后端 JAR、管理端静态文件、C 端 H5 静态文件均已构建完成，不需要在服务器安装 Maven 或 Node。Python 仅用于迁移、备份和恢复脚本。

## 2. 需要由接收团队填写的内容

复制 `source/deploy/migration.env.example` 为受限文件并填写：

- MySQL 主机、端口、目标数据库名；
- 迁移账号和迁移口令；该账号需要目标库初始化所需的建库、DDL、DML 权限；
- MySQL 客户端目录。

复制 `source/deploy/api.env.example` 为 `/etc/yunji/api.env` 并填写：

- `YUNJI_DB_URL`、`YUNJI_DB_USERNAME`、`YUNJI_DB_PASSWORD`；
- `YUNJI_REDIS_HOST`、`YUNJI_REDIS_PORT`、`YUNJI_REDIS_PASSWORD`；
- `YUNJI_MONITOR_PASSWORD`；
- 至少 48 个随机字符的 `YUNJI_TOKEN_SECRET`；
- 稳定保存的 `YUNJI_IDENTITY_HMAC_KEY`；
- Base64 编码的 32 字节 `YUNJI_IDENTITY_ENCRYPTION_KEY`；
- 实际附件目录 `YUNJI_STORAGE_ROOT`。

当前没有微信/企微资源时，`YUNJI_WECHAT_APP_ID` 和 `YUNJI_WECHAT_SECRET` 留空；不要填写 `YUNJI_LOCAL_SECRET`。身份 HMAC、加密密钥和 Token 密钥必须跨重启保持不变，配置文件权限为 0600。

Nginx 配置还要替换：

- `server_name`；
- TLS 证书和私钥路径；
- `/opt/yunji/current/admin/` 与 `/opt/yunji/current/client-h5/` 的实际发布路径。

## 3. 推荐安装顺序

1. 将包内 `artifacts/backend/agri-admin.jar` 放到发布目录的 `backend/agri-admin.jar`；将 `artifacts/admin` 放到 `admin/`，将 `artifacts/client-h5` 放到 `client-h5/`。将 `source/database`、`source/scripts`、`source/deploy` 一并放到同一发布根目录。
2. 创建运维虚拟环境并安装 Python 依赖：`python3 -m venv /opt/yunji/ops-venv && /opt/yunji/ops-venv/bin/python -m pip install -r scripts/requirements.txt`。后续使用该解释器执行脚本。
3. 创建 MySQL 迁移账号和应用账号。迁移账号只交给迁移脚本；应用账号只授予目标库 SELECT、INSERT、UPDATE、DELETE。
4. 导出迁移配置后执行：

   ```bash
   set -a
   . /etc/yunji/migration.env
   set +a
    /opt/yunji/ops-venv/bin/python scripts/database_ops.py migrate
    /opt/yunji/ops-venv/bin/python scripts/database_ops.py bootstrap
   ```

   DBA 已预创建空库时使用 `migrate`；只有迁移账号临时拥有全局 CREATE 且库不存在时才使用 `initialize`，随后立即回收全局权限。`bootstrap` 只在首次建库执行，会隐藏输入新的管理员口令并停用框架其他初始账号；升级时不要重跑。不要把口令写在命令行参数或聊天记录中。

5. 安装 `source/deploy/systemd/yunji-api.service`，确认 `ExecStart` 指向当前发布目录的 JAR，执行 `systemctl daemon-reload`、`systemctl enable --now yunji-api`。
6. 安装并修改 `source/deploy/nginx/yunji.conf`，先执行 `nginx -t`，再重载 Nginx。
7. 验证 API、管理端和 C 端 H5；确认 `/api/local`、`/api/v1/auth/customer/local`、OpenAPI、Actuator 和私有文件路径从外部均不可访问。

## 4. 试验验收边界

没有真实客户平台资源时，可以验收：管理端登录、资讯发布审核、公开 C 端浏览、管理端活动/评审/资料配置、私有附件票据、权限拒绝和备份恢复。收藏、订阅、活动报名等客户写操作需要真实身份或另行批准的试验身份，不得用生产 local gateway 冒充。

暂不验收：真实微信登录、微信/企微通知送达、微信真机体验版、正式公网切流。微信小程序构建产物位于 `artifacts/client-mp-weixin`，取得独立 AppID、HTTPS 合法域名和测试账号后再导入开发者工具联调。

试验完成后必须保留：迁移日志、systemd 日志、Nginx 日志、备份清单、恢复演练记录、服务器版本和配置哈希。试验环境的问题修复后重新生成交付包，不直接修改服务器上的文件作为最终交付。
