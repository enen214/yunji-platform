## 1. 需求核查与实施决定

核查输入为 ltjl 的聊天、开发待补清单、通用 Vue 警告说明和旧客户端的交互参照。输入文件和客户个人信息不复制到交付仓库。网关、证书、上线配置的解释适用于部署，原答复没有问题；它与控件边界不清楚分别处理。

| 反馈 | 本轮决定与交付 | 边界 |
| --- | --- | --- |

## 2. 源码与兼容设计

- `apps/client/src/styles/tokens.scss`：编译期 Sass 颜色常量；`app.scss` 编译到 H5 与小程序，关键颜色不再依赖运行时 `var(--color-*)`。配色保持原绿色体系。
- `apps/client/src/features/telemetry.ts`：`NativeExposureScope` 声明最小原生观察能力；隐藏页面取消计时、回调按代次隔离、同一列表曝光去重。未挂载时没有原生上下文就跳过观察，业务页面继续可用。
- `apps/client/src/pages/index/index.vue`：保留页面实例引用，在真正观察时解析 `$scope`，不把 Vue proxy 传给 uni 参数包装器。不要用 `$data` 替代页面上下文。
- `apps/admin/src/views/DeliveryCenter.vue`：规则、配置、统计与企微工作区。保留旧管理路由；企微新页面统一在 `/reminders/wecom*` 下，同用 `yunji:notification:manage`。
- 后端 `ReminderTrackingService.pauseByStaff`：角色权限、全局调度锁、乐观版本、原因校验、STAFF 审计；`ReminderBatchService.statistics`：服务端全量去重，不用当前页面行数作为统计。
- 新接口 `POST /api/v1/admin/reminders/rules/{id}/pause`，请求 `{expectedVersion,reason}`。原因去空白后至少 10 字、至多 500 字；成功返回 Tracking；401/403 权限拒绝、404 不存在、409 版本冲突或已暂停、422 参数错误。写请求沿用 `Idempotency-Key`。
- 统计新增 `trackedUsers/enabledUsers/dailyUsers/instantUsers`，旧字段保留；规则列表补 `title`。以导出的 `contracts/openapi.json` 为接口依据。
- 本轮无数据库迁移；继续 V1～V22，旧迁移不修改。未改变后端依赖、运行配置和平台就绪状态，未导入旧 demo 业务源码。

## 3. 统计口径

`trackedUsers` 是曾建立跟踪且仍保留规则记录的不同账号数，包含暂停规则，不是所有注册用户。

`enabledUsers` 要求账号 ACTIVE、未注销、提醒总开关打开、至少一条规则打开。`dailyUsers` 和 `instantUsers` 在相同条件下按模式分别去重；一个用户可同时计入两个模式，不能相加当总人数。它们表示配置意愿，不保证已有有效平台授权或一定可送达。

`activeRules` 仍保留原定义：规则 enabled=1 的条数；未额外按用户总开关过滤，不是人数。`states` 是批次量，`pendingChanges` 是待处理变化量。企微统计仅筛选 WECom 批次，全局规则数和待处理变化仅在总统计展示，不将全局用户量包装成已绑定企微人数。

## 4. 人工试验步骤

1. 按 README 安装依赖并构建。`python scripts/workbench.py start` 使用全新合成库。管理端 `http://127.0.0.1:5174/#/login`，测试管理员 `admin/admin123`；C 端 `http://127.0.0.1:5173/#/`。生产禁止使用这些夹具。
2. `python scripts/workbench.py code alice` 获取单次测试登录码；`python scripts/workbench.py authorize alice --quota 5` 仅提供合成授权。
3. C 端进入提醒页，检查“日常提醒 / 即时提醒”按钮、选中背景、规则卡片边框；查看全局设置、规则编辑、状态、历史和登录返回。窄屏下检查长标题、空列表、错误和禁用按钮。
4. 后台“提醒规则”选择启用规则，点击“暂停规则”，填写工单原因。保存后刷新仍暂停；审计 action 为 `REMINDER_OPERATOR_PAUSE`。在用户侧可自主恢复；并发修改后用旧页面提交应报冲突并提示刷新。
5. 后台“强提醒统计”核对人数与规则数区别。关闭用户总开关后当前启用人数变化；历史跟踪人数不随暂停规则减少。
6. “企业微信”组逐一进入五个页面。配置跳转到真实每日设置和模板编辑；任务处理页指导进入任务列表核实/补提。UNKNOWN 先核实，明确 FAILED 才补提；每次记录依据。日常提交仍等待员工在企微发送。
7. “通道监控”的“执行一次任务处理”影响所有启用通道，只用于排查；自动调度无须人持续点按钮。没有声称企微页面提供最后一步实际发送。
8. 活动总览点击“进入资料中心”；发布资料包/插件版本后查看下载和教程；未发布资料显示空态。没有活动与文件关联，不把普通资料中心描述为活动专属附件。
9. “关于云迹”无需请求 about API 即可显示；后台“协议管理”只有 terms/privacy 可新建。隐私和条款仍显示版本并可记录同意。运营需先在协议管理发布正式 terms/privacy 正文；初始化历史占位页不是正式协议。
10. 结束执行 `python scripts/workbench.py stop`。启动器不会延续旧人工试验数据，也不会接管其他进程的端口。

## 5. 微信开发工具接力

构建：`cd apps/client`，`npm run build:mp-weixin`；导入 `apps/client/dist/build/mp-weixin`。AppID、HTTPS API 地址按既有开发手册在构建前配置，不能导入 H5 目录或旧项目包。

登记 Git SHA、构建时间、开发工具版本、基础库、渲染器和设备。先验证登录、提醒、筛选弹层、资源卡、输入框的颜色/边框/点击区，再测数据加载与错误态；录制具体路径。首页曝光测试滚动停留、不足一秒移开、切后台返回和刷新列表；展开 Vue warning 栈确认是否还有其它路径。

`reports/client-compat.json` 证明编译产物和隔离生命周期的 10 项测试，不代表微信开发工具或手机已通过。若只在某基础库/渲染器出现问题，应附版本和调用栈继续定位，不要求客户先完成生产证书配置才受理界面问题。
