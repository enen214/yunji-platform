## 已实施的整改

使用实际部署 JAR 的 `BOOT-INF/lib` 生成 CycloneDX；不把根 reactor 内未部署的工具模块当作运行依赖。无法从嵌套 pom.properties 取坐标的库必须与 Maven 缓存字节哈希一致；未识别项或扫描错误都不能视为安全。

Spring Boot 3.5.16、Tomcat 10.1.60、Jackson 2.21.7、Netty 4.1.137.Final、Log4j 2.26.1、Bouncy Castle 1.86、POI 5.5.1、jsoup 1.23.1 等兼容更新已构建并执行回归。原 fastjson 1 被 `com.alibaba:fastjson:2.0.65` 的兼容 API 替代；新业务 HTTP 模型使用 Jackson 和显式 DTO。

部署 reactor 去除了 job、generator、workflow、PostgreSQL 等未使用能力；运行容器统一 Tomcat，删除 Undertow 配置。数据库采用 Hikari 单库，运行包移除 dynamic-datasource 及其表达式执行面。optional generator 源码仍保留在公司基座目录，并自行声明多数据源依赖；不进入 `-pl agri-admin -am` 交付构建和 SBOM。不要以 root reactor 全量构建重新把这些工具带入部署包。

## C 端仍阻塞的供应商问题

本轮 npm 审计链来自 `braces <=3.0.3` 的深层嵌套栈耗尽公告 **GHSA-vfj7-8cjw-p6xm**，向 micromatch、fast-glob、chokidar 和 uni-app 构建工具传播，17 项包记录不代表 17 条独立漏洞。当前上游可用版本没有公告认可的修复。强制降级/跨大版本覆盖会破坏 uni-app 兼容链，不能当作专业修复。

可达性判断：受影响解析器处理构建/开发工具的 glob，不是业务 HTTP 的 JSON 解析器。生产部署只上传 H5、小程序和管理员静态产物，不上传 node_modules、不运行 Vite/npm 开发服务，服务器使用已验收的 JAR。构建输入来自受控源码和配置；依赖的高危评级仍保留，以上限制不等同负责方接受风险，也不能把 audit 结果改成 0。

暂定处理：固定 lockfile，隔离构建，不向不可信用户提供 glob/编译入口；跟踪 uni-app/相关包正式兼容修复。后续在独立分支升级后重跑 typecheck、H5、小程序、真实页面回归及安全扫描。如果平台团队选择维护替代构建链或供应商安全补丁，需形成可审查实现和兼容证据，再更新锁文件。禁止 `npm audit fix --force` 或伪造安全忽略项。

GitHub CI 的构建步骤与依赖门禁分开：构建可以通过，安全断言仍会因这 17 项失败并上传证据。这是已知阻塞的如实结果，不能把整个 CI 失败解释成应用不能构建。正式发布前需要修复，或由负责方针对具体风险作书面决定；本工程未自动作该决定。

公告数据库结果不能证明完全没有漏洞。每个版本都必须重新生成实际 JAR SBOM、刷新 npm/OSV，并与源码指纹一致；本报告不覆盖平台配置、业务逻辑、渗透测试或目标机基础软件。
