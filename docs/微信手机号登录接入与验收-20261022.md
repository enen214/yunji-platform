## 1. 复核结论与范围

旧 C 端使用 `getPhoneNumber` 获取手机号授权码，再用 `uni.login` 获取身份登录码。旧后端以 `jscode2session` 换取 openid，并通过官方手机号接口换取手机号。这不是本地假登录；手机号接口可能消耗平台额度，测试/体验版不等于免额度。

从旧项目指定枚举中的参数值提取 AppID/AppSecret，并与旧 C 端 manifest 核对 AppID 一致。配置仅保存到 `.runtime/wechat-login-private.json`，限制本机账户访问；前端公开 AppID 保存到被 Git 忽略的 `apps/client/.env.wechat.local`。未复制旧业务源文件、登录策略、用户表、SQL、token 或日志代码。没有全量导入旧 application.yml。

已在 2026-10-22 调用微信官方 `stable_token`，`force_refresh=false`，返回有效应用 token。检查未调用手机号 API，未发消息，也未将返回 token 输出或持久化。此结果仅证明当前凭据可用，不能证明手机号权限、用户授权、开发者角色、域名或整条微信登录链路已经通过。没有修改旧系统的配置，也没有使用强制刷新 token。脱敏结果归档在 `reports/wechat-credential-check.json`，它不参与真实平台 PASS 判定。

## 2. 接口和账户边界

新增 `POST /api/v1/auth/customer/wechat/native`：

```json
{"appId":"wx0000000000000000","code":"本次wx.login产生的code","phoneCode":"本次getPhoneNumber产生的code"}
```

示例中的 AppID 和 code 是占位值。普通微信登录省略 `phoneCode`；一键手机号登录必须提交本次授权返回的独立 `phoneCode`。两种 code 不可交换、复用或写入日志。接口不接受客户端手机号码作为身份依据。

- 此入口在 local/prod 均调用真实微信；未配置凭据返回 503。不会因 local profile 将真实请求变成合成账号。
- 旧 `/api/v1/auth/customer/wechat` 保留历史兼容语义：local 下消费合成码，非 local 下做官方身份登录。新 C 端只使用 `/wechat/native`；合成登录仍用 `/api/v1/auth/customer/local`。
- 校验前后端 AppID 一致，先换取可信 openid，再按需获取手机号；手机号返回结果的 watermark.appid 必须一致。
- 手机号授权失败不降级成“手机号登录成功”，也不创建客户会话。用户可以重新授权，或主动选择普通微信登录。
- 账号唯一依据仍是 `tenant + WECHAT + AppID + openid哈希`。同一微信身份的两种登录进入同一账号，不按手机号查找或合并旧账号；不会迁入旧数据或旧 token。
- 只保存服务端验证后的 `phone_masked`，例如 `138****1234`；不足 10 位的号码仅保留首位与末两位，避免短号码的所有原始数字都留在脱敏值中。不保存完整手机号，不新增数据库迁移。普通微信登录不会清空已有脱敏号码，注销按原策略清除。脱敏号码仅用于展示，不能当作短信接收地址、实名或企微绑定证明。
- 会话响应只返回原有 accessToken/expiresIn/userId/realm，不返回 openid、session_key、完整手机号码或平台 access_token。
- 审计区分真实微信登录与合成登录，记录是否本次获得手机号授权，不记录具体号码或授权码。

相关代码：`identity/api/IdentityController`、`identity/infrastructure/WechatGateway`、`identity/application/IdentityService`，前端共用 `features/wechat-login.ts`。弹窗 `LoginSheet.vue` 和独立 `pages/login/index.vue` 均已接线。

## 3. 网络与交互规则

登录按钮必须由用户点击；先同意协议，才启用 `getPhoneNumber`。拒绝授权给出明确提示，不自动调用手机号接口。保留普通微信登录，公开浏览无需强制手机号授权。正在登录时禁用重复提交；离开页面后旧响应不得覆盖当前账号。

真实身份/手机号请求只访问代码固定的微信官方 HTTPS 域名，不接受客户端传入供应商地址。连接超时 5 秒，请求超时 10 秒，响应最多 16 KiB，不跟随重定向。应用 token 使用 `stable_token` 的非强制刷新模式，保存在服务端内存，提前 60 秒过期；明确 token 失效时清理缓存，下次用户主动发起登录再获取。

不自动重试身份码或手机号码，不在不确定的网络失败后重复扣接口额度。每次重试由用户重新触发，重新取得 code。失败信息不回显供应商原始响应、URL、凭据或号码。平台临时不可用、额度/权限不足、IP 白名单或凭据问题返回可理解的错误，普通微信登录作为用户主动选择的替代方式。

手机号授权与订阅消息授权、企微绑定完全独立。此次登录成功不会自动授予提醒额度，不会开启真实通知调度。

## 4. 这台开发机怎么试

先停止已经运行的合成工作台，再在仓库根目录打开终端执行：

```powershell
python scripts/workbench.py start --wechat-login-config .runtime/wechat-login-private.json
```

保持终端运行。这个参数显式启用真实微信登录，提醒仍使用本地合成通道。默认不带参数的工作台会清空微信应用凭据，继续纯合成测试。工作台数据库是临时库，重开工作台会换库、换身份加密密钥；不能把它当持久测试服务器。

另开终端构建微信专用测试包：

```powershell
python scripts/build_wechat_test.py
```

脚本读取前端 `.env.wechat.local` 的公开 AppID；不读取后端私有配置或 AppSecret。调用 uni-app 编译，输出到 `.runtime/wechat-devtools`，只为生成的 `project.config.json` 填写 AppID，不改受版本控制的 manifest，也不覆盖标准验收构建产物。

1. 微信开发者工具导入 `D:\yunjiwxCongxie\yunji-platform\.runtime\wechat-devtools`。使用有该小程序开发权限的微信账号，不能使用游客 AppID。
2. 本机模拟器请求 `http://127.0.0.1:18088` 时，仅开发者工具本地测试可临时勾选“不校验合法域名、web-view、TLS/HTTPS 证书”。该设置不是上线方案。
3. 打开“我的”或需要登录的功能，同意协议，点击“手机号一键登录”，完成微信原生授权。
4. 验证登录后个人状态、关注和退出；再次登录应进入同一账号。拒绝授权应保持未登录；普通微信登录应不请求手机号。
5. H5 `http://127.0.0.1:5173/#/` 没有微信原生手机号授权能力，用合成登录验证 H5。管理员仍是原 Web 登录。
6. 真机的 `127.0.0.1` 指手机本身，不能直接用。体验版/真机应把 `.env.wechat.local` 的 `VITE_API_BASE_URL` 改成目标后端可达的 HTTPS 域名并重新构建；后端正式域名、证书、合法域名和出口 IP 由接收团队配置。不要把 local 工作台暴露到公网。
7. 结束执行 `python scripts/workbench.py stop`，只停止该工作台启动的服务。

甲方还应在小程序后台的隐私保护指引中如实声明手机号获取用途，并在重制版后台发布与实际处理一致的隐私政策：本功能用于手机号授权登录与脱敏显示，后台不保留完整号码。原生隐私授权由微信运行时处理，不通过前端伪造接受状态。

如果缺少微信开发者权限，请甲方在该小程序后台添加测试人员；有效 AppSecret 不能替代开发者权限。若微信工具或平台限制模拟器取手机号，需要使用已配置 HTTPS 后端的真机验证，不伪造手机号结果绕过。

## 5. 部署与回退

部署时通过既有环境项 `YUNJI_WECHAT_APP_ID`、`YUNJI_WECHAT_SECRET` 配置后端。前端开发者工具/体验版 AppID 必须与后端一致；前端 helper 读取微信运行时 AppID。密钥禁止使用 `VITE_` 前缀、写进小程序或提交 Git。

生产和持续试验环境必须使用持久数据库、固定的身份 HMAC/加密密钥及正式安全配置。不要复制工作台随机密钥或临时客户库。无数据库版本升级，本轮仍为 V1～V22；回退需同时回退前后端版本。旧客户端仍可用历史登录接口，新客户端依赖 `/wechat/native`，不能只更新一端。

本机私有配置不会随 GitHub 上传。接收团队需由甲方安全提供或配置对应密钥；此前文档“禁止沿用旧 demo 配置”的例外仅限本次用户授权的这一对微信应用凭据，不代表可以复制旧整体配置。测试包不会自动上传微信平台，本轮也不自动推送 GitHub。

## 6. 验收证据与剩余动作

- `WechatGatewayTest`：官方协议的本地 HTTP 替身，覆盖不同 code、token 缓存、应用校验、普通登录、失效 code、手机号失败不降级、watermark、错误响应、超限及重定向。
- `WechatLoginBoundaryTest`：native 入口不走合成分支、只保存验证后的脱敏值、普通登录保留已有关联、真实审计与会话字段限制。
- `tests/wechat_login.cjs` / `scripts/wechat_login_acceptance.py`：前端拒绝授权、不同 code、运行时 AppID、取消后晚到响应、双击互斥、同意前不登录和编译后原生授权按钮。
- API 负向回归检查缺配置、空手机号码、超长身份码；原合成接口仍验证单次码与禁止重放。
- 常规构建/API/浏览器/提醒/运维回归结果在 `reports`，新增本地登录证据为 `reports/wechat-login.json`。本地门禁包含本轮登录回归；微信平台验收门禁继续独立。

真实微信最终验收仍需要：有开发权限的账号主动授权，验证手机号接口能力/额度、原生取消与拒绝、登录和退出、同一 openid 重登、体验版合法域名及真机网络。凭据检查成功不等同这些项目通过。不得因此把 `reports/platform-acceptance.json` 改成 PASS。
