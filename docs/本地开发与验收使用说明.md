## 1. 环境要求

- **本地运行器已验证平台：Windows**；Python 3.10+、Node.js/npm、JDK 21、Maven 3.9。
- MySQL 8 服务端和客户端；Redis 7。
- 浏览器验收需要 Playwright Chromium。
- Linux 服务器使用部署手册中的已构建产物和独立数据库工具；本地运行器在 Linux 的等价行为没有作为本项目证据。

Windows 如果工具不在默认路径，在启动脚本的同一个 PowerShell 终端设置下表环境变量；默认值是研发机路径，换电脑必须核对。

| 变量 | 内容 |
| --- | --- |
| `YUNJI_TEST_MYSQL_BIN` | 含 `mysql.exe`、`mysqld.exe`、`mysqladmin.exe`、`mysqldump.exe` 的目录 |
| `YUNJI_TEST_MAVEN` | `mvn.cmd` 完整路径 |
| `YUNJI_TEST_MAVEN_SETTINGS` | 可选，受控 Maven settings 文件路径，不提交含凭据的文件 |
| `YUNJI_TEST_JAVA` | `java.exe` 完整路径 |
| `YUNJI_REDIS_SERVER` | `redis-server.exe` 完整路径 |

PowerShell 使用 `$env:YUNJI_TEST_MAVEN = '实际安装路径\bin\mvn.cmd'` 这样的赋值方式。Node/npm 和 Python 需可从 PATH 调用。不要把填写了密码的 `.env` 提交到 Git。

## 2. 获取代码和首次安装

私有仓库成员从空目录获取本次交接分支：

```powershell
git clone --branch feature/brand-yunji --single-branch https://github.com/qianyue303jiaojie/yunji-platform.git
Set-Location yunji-platform
```

仓库权限由 GitHub 所有者邀请。不要把 PAT、密码或平台密钥写进命令、聊天或版本库。

```powershell
python -m pip install -r scripts/requirements.txt
Set-Location apps/admin
npm ci
Set-Location ../client
npm ci
Set-Location ../../tests
npm ci
npx playwright install chromium
Set-Location ..
```

`scripts/requirements.txt` 当前包含 `bcrypt==4.3.0` 和 `PyYAML==6.0.2`。安装失败时记录 Python 版本和错误，不要跳过依赖后把不完整报告交给接收团队。

## 3. 启动人工工作台

从仓库根目录执行：

```powershell
python scripts/workbench.py start
```

首次运行前先从仓库根目录执行 `python scripts/build_acceptance.py`，确认当前源码可构建。工作台会创建新 MySQL、Redis、API 和两个前端服务，并在启动日志提示服务就绪。地址：

- C 端 H5：`http://127.0.0.1:5173/#/`
- 管理端：`http://127.0.0.1:5174/#/login`
- API：`http://127.0.0.1:18088`

获取 C 端合成单次登录码：

```powershell
python scripts/workbench.py code alice
```

码有效期约两分钟，只能使用一次。`authorize` 仅用于本地模拟订阅额度：

```powershell
python scripts/workbench.py authorize alice --quota 5
python scripts/workbench.py status
```

本地管理端夹具账号只用于隔离工作台：

| 账号 | 密码 | 角色 |
| --- | --- | --- |
| `admin` | `admin123` | 管理员 |
| `test1` | `666666` | 创作者 |
| `test` | `666666` | 审核员 |

不要把这些账号用于任何服务器或生产环境。结束时执行：

```powershell
python scripts/workbench.py stop
```

如果端口被占用，先停止上一次工作台；运行器不会接管已有进程。

## 4. 人工验收路径

### C 端

1. 打开 H5 首页，确认左上角品牌为“云迹”。
2. 使用顶栏“全部/竞赛双创/学业修读”等入口切换板块。
3. 使用“全部学校与组织”筛选学校或组织；分类不会在底部重复出现。
   - 首页无搜索、无板块和无组织筛选时默认只展示 `hot_weight > 0` 的热点资讯；新建草稿默认热点为 0，首页暂时为空属于正常结果。进入板块、组织或搜索后会关闭热点限定。
4. 搜索资讯，打开详情，检查摘要、正文、解读、原始信息、来源和有效期。
5. 登录后验证收藏、关注、信息盒子、提醒、历史、活动、资料和反馈。
6. 在“我的订阅”查看板块推送、关注更新和更替推送；更替后关注与强提醒应自动迁移，历史仍可查看，授权额度不增加。
7. 通过“我的”退出登录，再次进入受保护页面应回到登录页且不会循环。

### 管理端

1. 用管理员登录，检查资讯草稿、板块单选、关键词、来源、解读、有效期、热点和重要度。
2. 执行提交审核、审核通过、发布、下线和内容更替，确认旧正文不可公开访问。
3. 检查分类、组织、关键词、活动、评审、资料包、文件、提醒、举报、反馈、分析和审计页面。
4. 用创作者和审核员账号检查菜单与按钮权限；服务端拒绝越权请求。

## 6. 构建产物

```powershell
Push-Location apps/client
npm run build:h5
npm run build:mp-weixin
Pop-Location
Push-Location apps/admin
npm run typecheck
npm run build -- --base=/admin/
Pop-Location
```

后端（Maven 已加入 PATH 时）：

```powershell
Push-Location backend
mvn -B -q -pl agri-admin -am verify
Pop-Location
```

如果 Maven 不在 PATH，在当前终端设置 `YUNJI_TEST_MAVEN` 后运行 `python scripts/build_acceptance.py`；不要把某台开发机的绝对路径写入交接脚本。

上述命令从仓库根目录执行。H5 产物在 `apps/client/dist/build/h5`，微信小程序产物在 `apps/client/dist/build/mp-weixin`，管理端产物在 `apps/admin/dist`。小程序 `VITE_API_BASE_URL` 应在构建前配置为目标 API 地址。真实微信专用包使用 `python scripts/build_wechat_test.py` 从私有前端环境文件读取公开 AppID 并填充生成项目配置；运行时读取实际 AppID，不必修改受追踪的 manifest。生产构建隐藏合成登录，不把已经编译的 API 地址当作运行时变量。微信 AppID、HTTPS 合法域名和真机体验版仍需微信开发者工具及平台资源验收。

## 7. 常见问题

- **页面空白**：先检查 API 18088 是否启动，再查看 `.runtime/run-*/api.log`。
- **登录码失效**：重新执行 `workbench.py code alice`；码是一次性且短时有效。
- **端口占用**：执行 `workbench.py stop`，确认 33308、16379、18088、5173、5174 释放后重试。
- **迁移失败**：保留日志，检查 MySQL 版本、账号权限和 `schema_history`；不要修改已应用迁移后强行重跑。
- **构建报告过时**：重新执行 `build_acceptance.py`，再执行依赖源码指纹的验收脚本。
- **小程序无法请求 API**：确认使用 HTTPS 合法域名和 `VITE_API_BASE_URL`；`127.0.0.1` 可用于本机 H5 和开发者工具本地模拟器，不能指向真机外的开发电脑。
- **来源核查无法重跑**：`provenance_audit.py` 需要研发侧工程外的授权基座提交和样本路径。干净接收机使用已交付的 `reports/provenance.json`，不要把 `yangben` 复制进仓库。

## 8. 停止、清理和交接

工作台停止后，`.runtime/run-*` 只作为本机证据，可按本机留存策略清理；不要删除构建缓存来“修复”功能。交付团队使用 `python scripts/delivery_bundle.py --destination <工程外目录>` 生成源码、报告和构建物交接包。交接包不含 `yangben`、旧数据、依赖缓存、数据库备份、私钥或本地工作台密钥。

生产部署、Linux、TLS、systemd、备份恢复、真实微信/企微和安全整改不在本说明的本地通过范围内，必须按 `docs/部署团队交接操作书.md` 和 `docs/交付与剩余门禁.md` 单独验收。
